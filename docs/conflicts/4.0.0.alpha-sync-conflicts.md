# Conflict audit: upstream sync v3.8.3 -> quattro (4.0.0-alpha)

Repo: omarchy-mac-fedora. Target branch: `quattro` (branched from `sync/upstream-v3.8.2` = the fork's
merged 3.8.3 state, `998302d9`). This becomes the repo's default branch; the 3.8.3 line is preserved on
`sync/upstream-v3.8.2`.
Upstream source: https://github.com/basecamp/omarchy, branch `quattro` fetched under `upstream/quattro`
(`9030ba87`, version `4.0.0.alpha`).
Base of the sync: `git merge-base` = `ae7365f9` (a true 3-way base; quattro diverged there).

Strategy: a single `git merge --no-ff upstream/quattro` (never rebase, never squash), so the merge commit
carries both parents and all 1117 upstream commits stay in history with their authors intact. quattro is
an alpha branch with no intermediate release tags, so it is one merge, not a tag-by-tag sequence.

Fork-side invariants that win every conflict: **dnf not pacman; aarch64 only (skip
Intel/NVIDIA/Framework/ASUS/Surface/Dell/T2/Lenovo x86 hardware); alacritty not ghostty; dracut not
mkinitcpio/limine; git-clone delivery, not the pacman package model.**

**What quattro is:** not a normal bump — a re-platforming. It (1) deletes the fork's entire old
`install/` bootstrap architecture (`boot.sh`, `install.sh`, `install/{config,first-run,packaging,
preflight,post-install,login}/*`) and replaces it with a package-post-install layout; (2) replaces
waybar+walker+elephant+mako+swayosd with a Quickshell QML shell (`shell/`); (3) moves hypr config from
`.conf` to `.lua`. So most conflicts are "the fork's old file was retired upstream." The fork's Fedora
logic is NOT lost — it stays in history on `sync/upstream-v3.8.2` and is re-homed onto quattro's new
files in the Fedora-adaptation phases (P1-P6 of the port plan) rather than in the merge itself.

Conflict landscape at merge start: **188 conflicted paths** (1440 auto-merged cleanly). Resolved below.
